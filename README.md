# Vanta Core — پنل VLESS روی Railway

**Vanta Core** یک پنل مدیریت کانفیگ‌های VLESS+WS است که روی
[Railway](https://railway.app) به‌عنوان یک پروسه‌ی Node.js بلندمدت اجرا
می‌شود (نه سرورلس). این پروژه بازنویسی کامل و مستقل نسخه‌های قبلی است:
نام، امضا، تم و ساختار همه‌چیز تازه نوشته شده و یک **سپر ضد بن**
(elaborate stealth shield) روی آن سوار شده است.

> ⚠️ استفاده از این پروژه برای دور زدن قوانین Railway یا هر سرویس میزبانی
> خلاف ToS آن‌هاست و مسئولیتش با شماست. مکانیزم «ضد بن» این پروژه صرفاً
> لایه‌های مخفی‌سازی و محافظت فنی است، نه تضمینی برای بقای اکانت.

---

## ✨ امکانات

- **رله‌ی VLESS + WebSocket** روی مسیر `/core` — بدون سقف زمانی اتصال
  (مزیت پروسه‌ی بلندمدت Railway)، پشتیبانی TCP و UDP (DNS/QUIC)،
  backpressure دوطرفه و ثبت مصرف دوره‌ای.
- **پنل مدیریت فارسی** با تم «Aurora Glass» (شیشه‌ای با شفق سایان/بنفش)،
  کاملاً ریسپانسیو.
- **کانفیگ‌های چندکاربره**: سقف ترافیک، انقضا، محدودیت IP هم‌زمان،
  پروکسی خروجی SOCKS5/HTTP (چرخشی)، لیست مسدودسازی مقصد، آی‌پی‌های تمیز
  با چرخش خودکار و برچسب لوکیشن.
- **سابسکریپشن استاندارد**: هر کانفیگ یک لینک `/sub/<uuid>` با هدر
  `Subscription-Userinfo` (مصرف/سقف/انقضا) — سازگار با کلاینت‌های رایج.
- **ربات تلگرام**: ساخت/ویرایش/حذف کانفیگ، ارسال لینک، پیام همگانی،
  مدیریت ادمین‌ها و بکاپ — همه از داخل تلگرام.
- **بکاپ/بازیابی JSON** (جایگزینی کامل یا ادغام).
- **اسکن آی‌پی تمیز** از رنج‌های رسمی Cloudflare بدون نیاز به سرویس بیرونی.

## 🛡️ مکانیزم ضد بن (سپر Vanta)

Railway اکانت‌ها را معمولاً به‌خاطر (۱) ترافیک/الگوی غیرعادی، (۲) اسکن و
بروت‌فورس، یا (۳) شکایت/بازرسی محتوای دامنه می‌بندد. سپر این پروژه روی
هر سه محور کار می‌کند:

| لایه | چه می‌کند |
|---|---|
| **صفحه‌ی قلابی (decoy)** | دامنه‌ی شما برای همه‌ی بازدیدکننده‌ها (از جمله بازرس‌ها و خزنده‌ها) یک سایت SaaS معمولی به نام «Nimbus Notes» نشان می‌دهد. هیچ اثری از پروکسی/پنل در مسیرهای عمومی نیست. |
| **مسیر مخفی پنل** | ورود پنل فقط روی `https://دامنه/<ADMIN_PATH>/` ممکن است — پیش‌فرض `/vanta-admin`. از پنل قابل تغییر است (بدون ری‌استارت). `/dashboard` و `/api/*` عمومی وجود ندارند؛ همه 404 قلابی می‌گیرند. |
| **مسک‌کردن پروتکل** | مسیر WebSocket رله `/core` است (نه `/ws` رایج)؛ درخواست بدون Upgrade به آن، 404 قلابی می‌گیرد. پیام‌های کلوز رله عمداً بی‌الگو هستند (`closing`، `limit exceeded`) تا امضای «VLESS panel» از آن‌ها استخراج نشود. |
| **فیلتر اسکنر** | User-Agentهای شناخته‌شده‌ی ابزارها (curl، wget، python-requests، botها و…) مستقیم 404 می‌گیرند. قابل خاموش‌کردن. |
| **محدودیت نرخ** | سقف درخواست/دقیقه برای مسیرهای ادمین و سقف هندشیک/دقیقه برای هر IP روی WebSocket — هر دو از پنل قابل تنظیم. |
| **قفل تلاش ورود** | بعد از N رمز غلط (پیش‌فرض ۵)، آن IP به‌مدت ۱۵ دقیقه از ورود محروم می‌شود (ذخیره در Redis؛ در ری‌استارت هم می‌ماند). |
| **کلید پنیک 🧊** | با یک کلیک از پنل (یا `/panic 30` در ربات تلگرام) کل سرویس «سرد» می‌شود: همه‌ی اتصال‌های زنده‌ی رله فوراً بسته می‌شوند، هندشیک جدید رد می‌شود، سابسکریپشن 404 می‌دهد و ورود پنل قفل است — تا وقتی خودت خاموشش کنی. |
| **سقف ترافیک کل** | مهم‌ترین عامل بن، مصرف غیرعادی است. سقف GB ست کن؛ با رسیدن مصرفِ همه‌ی کانفیگ‌ها به آن، رله‌ها خودکار بسته می‌شوند و دیگر بایتی خارج نمی‌شود (پنل زنده می‌ماند). |
| **ماسک IP در لاگ‌ها** | در لاگ اتصال‌ها و رویدادهای امنیتی، بایت آخر IPv4 ستاره می‌شود (`1.2.3.x`) تا در صورت درز، حریم خصوصی لو نرود. |
| **noindex همه‌جا** | هدر `X-Robots-Tag: noindex, nofollow` روی همه‌ی صفحات + متای robots؛ دامنه در موتورهای جستجو ایندکس نمی‌شود. |
| **رویدادهای امنیتی** | هرچه سپر می‌بیند (رمز غلط، قفل، اسکنر، محدودیت نرخ، تغییر مسیر پنل، پنیک) در تب «امنیت و ضد بن» با زمان و IP ماسک‌شده ثبت می‌شود. |

### نکته‌های عملی برای بن‌نشدن

1. **سقف ترافیک ست کن** (تب امنیت → سقف ترافیک کل). مصرف دیتابیس/شبکه‌ی
   نرمال یک اپ کوچک با پروکسی پرمصرف فرق دارد؛ سقف، تفاوت را پنهان می‌کند.
2. **مسیر مخفی پنل را عوض کن** و آن را با هیچ‌کس به اشتراک نگذار.
3. **PANIC_KEY را ست کن** (اختیاری؛ متغیر محیطی) — مقدار اولیه‌ی پنیک.
4. روی دامنه‌ی سفارشی، **Cloudflare (ابر نارنجی)** فعال کن؛ آن‌وقت ترفند
   «آی‌پی تمیز» هم جواب می‌دهد و ترافیک از IPهای خود Railway رد نمی‌شود.
5. اتصال‌های بلند سالم‌اند، ولی اگر سرویس پرترافیک شد، مصرف را در تب
   امنیت زیر نظر بگیر.

## 🚀 دیپلوی روی Railway

1. این ریپو را به GitHub پوش کن و در Railway: **New Project → Deploy from
   GitHub repo** (Railway با Nixpacks خودش `npm install && npm start` را
   اجرا می‌کند).
2. یک Redis اضافه کن: **+ New → Database → Redis**.
3. متغیرهای محیطی سرویس اصلی:

| متغیر | اجباری | توضیح |
|---|---|---|
| `REDIS_URL` | بله | رفرنس `${{Redis.REDIS_URL}}` |
| `ADMIN_PASS` | بله | رمز ورود پنل |
| `ADMIN_USER` | خیر | پیش‌فرض `admin` |
| `SESSION_SECRET` | توصیه‌شده | رشته‌ی تصادفی طولانی برای امضای سشن |
| `ADMIN_PATH` | خیر | مسیر مخفی پنل (پیش‌فرض `vanta-admin`) — بعداً از پنل هم قابل تغییر |
| `TRAFFIC_CEILING_GB` | خیر | سقف ترافیک کل به گیگابایت (۰=بی‌سقف) — از پنل هم قابل تغییر |
| `SHIELD_STRICT` | خیر | `off` = غیرفعال‌کردن فیلتر اسکنر |
| `PANIC_KEY` | خیر | مقدار اولیه‌ی کلید پنیک (رزرو) |
| `PUBLIC_HOST` | خیر | اگر دامنه‌ی سفارشی داری و می‌خواهی لینک‌ها همان دامنه را نشان دهند |
| `PORT` | نه | Railway تزریق می‌کند |

4. در **Networking** یک دامنه‌ی عمومی بساز.
5. برو به `https://دامنه/<ADMIN_PATH>/` و وارد شو.
6. اولین کار: در تب «امنیت و ضد بن» سقف ترافیک و تنظیمات سپر را مرور کن.

### ساخت لینک

از پنل یک کانفیگ بساز؛ لینک `vless://` (به‌ازای هر آی‌پی تمیز یکی) و
لینک سابسکریپشن آماده می‌شود. QR و دانلود txt هم هست.

## 🤖 ربات تلگرام

از پنل → تب «ربات تلگرام» توکن BotFather را بگذار و فعال کن (webhook
خودکار ست می‌شود). دستورهای ادمین: `/start` `/admin` `/backup`
`/panic 30` `/panic 0` `/addadmin` `/deladmin` `/cancel`.

## 🗂️ ساختار پروژه

```
server.js          نقطه‌ی ورود (HTTP + upgrade WS + heartbeat)
src/app.js         روتر اصلی (decoy، پنل مخفی، API، ساب، وب‌هوک)
src/relay.js       موتور رله VLESS (TCP/UDP، backpressure، kill-switch)
src/vless.js       پارس/ساخت هدر VLESS
src/uplink.js      اتصال خروجی + پروکسی SOCKS5/HTTP
src/netstream.js   TCP خام با ظاهر Web Streams
src/firewall.js    لیست مسدودسازی مقصد (IP/CIDR/دامنه)
src/store.js       VaultStore روی Redis (کانفیگ‌ها، مصرف، لاگ، امنیت)
src/stealth.js     سپر ضد بن (پنیک، سقف ترافیک، rate limit، قفل ورود…)
src/decoy.js       صفحه‌ی قلابی عمومی
src/bot.js         ربات تلگرام
src/session.js     کوکی سشن HMAC
src/linkforge.js   ساخت لینک vless/سابسکریپشن
src/webbridge.js   پل Node Request/Response ↔ Web Request/Response
src/theme.js       تم Aurora Glass
src/ui-login.js    صفحه‌ی ورود
src/ui-dash.js     داشبورد
public/qrcode.min.js  کتابخانه‌ی QR (لوکال)
test/              تست‌ها (تولید لینک، فایروال، هندشیک VLESS، HTTP، سپر)
```

## 🔬 تست

```bash
npm install
npm test
```

تست‌ها شامل: پارس هدر VLESS، منطق فایروال (CIDR/دامنه)، ساخت لینک،
رمزنگاری سشن، ماسک IP، محدودیت نرخ، یک سرور واقعی با Redis فیک
(ورود، decoy، مسیر مخفی، قفل ورود، پنیک، سقف ترافیک، ساخت کانفیگ،
سابسکریپشن) و یک هندشیک VLESS+WS کامل از طریق یک سرور HTTP محلی
(اتصال واقعی TCP به سرور تست و رله شدن بایت‌ها).
